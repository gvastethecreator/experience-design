# Specialist handoff

This skill does its job alone: it frames the decision, gathers evidence, designs the journey, and defines the test. Some results need specialist work that is outside its scope. State the boundary and hand off the decision, not a vague request.

## Out of scope here

- Implementing or polishing an existing web interface, a new visual direction, or a broad visual redesign. The user outcome, task, and acceptance criteria stay here; visual execution belongs to whoever owns the interface.
- Small additive fixes that need no research. When the friction and the fix are both obvious, say so and skip the full process.
- Producing comparable visual variants or shareable prototypes. Prototype here only when an interaction is needed to decide.
- Deep specialist audits such as typography, color systems, layout grids, or formal accessibility conformance. Name the specific question the specialist must answer.
- Ideation of brand-new product capabilities. That is not a diagnosis of a current task, and a saved idea does not authorize implementation.
- Native, game, or 3D implementation. Formulate the research and interaction contract without claiming expertise in each renderer.

## Minimum handoff

Pass mode and authority, task, context, current state, reusable evidence, decision, requirements to preserve, risks, criteria, and pending test. The specialist returns changes and evidence within the same scope. Do not duplicate tickets, reports, or approval. Choosing a design does not imply publishing it.
